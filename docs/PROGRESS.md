## 現在のブロッカー / 要判断

1. **遠距離の観測が近距離スキャンを劣化させる（Phase 6.5 で修正・実機未確認）**: ユーザ指摘「近くでスキャンして精度が上がっても、遠くから同じ場所が写り込むとまた精度が落ちるのでは？」→ **その通りだった**。3 経路すべてで劣化していた: (a) 色は 1/d 重みでも遠距離観測が**累積し続ける**ので近距離の色を薄める、(b) 占有は距離無関係に +1 で、遠距離ノイズが**きれいな面の周りに誤セルを作る**、(c) カービングは遠距離の誤差の大きい深度が「面より奥」と読むと**正しい面を削る**。マップ作成用途なのに品質が単調改善しない設計の穴。→ **セルごとに `bestDist`（最も近くから観測した距離）を記憶し、非対称ルール**を導入: **より近い観測は追加・更新・カービングすべて可**、**`qualityRatio`(1.5) 倍より遠い観測はそのセルに一切触れない**。これで一度近くで撮った所は後から遠くに写り込んでも劣化せず、品質は上がる一方になる。残る限界: 遠距離観測が**未観測の場所に新しい誤セルを作る**ことは防げない（ただし近づけばカービングで消える＝自己修復）。
2. **占有値の無制限増加＝カービング/しきい値が無効化していた（Phase 6.4 で修正・実機確認済）**: Phase 6.3 のスライダーが「変えても分からない」と報告され、原因を数値で特定 —
   - 深度は毎フレーム **3,600 点**（160×90 / stride 2）。1 か所を見続けると 1 セルが **毎秒 +30〜60**、数秒で `count` が数百に育つ。**ノイズも同様に育つ**ため、`minObs` 3 でも 14 でも一瞬で超え、**しきい値として機能していなかった**（＝スライダーが効かない）。
   - カービングの減算は「毎フレーム `CARVE_BUDGET` 個ずつ検査」＝ 25 万描画で **1 周 0.5〜1 秒 → 毎秒 −2 程度**。加算 +30〜60/秒 に対して桁違いに弱く、しかも count が数百まで育っているため **消えるのに数分**かかっていた（＝「一応消える」が「また出る」）。
   - → **占有値に上限 `OCC_MAX`(10) を設定**（色の平均は従来どおり無制限に精緻化）。加算は 10 で頭打ち、カービングは `CARVE_MISS`(2)/回、`CARVE_BUDGET` を 16,000 に増やし、**約 1〜2 秒で消える**ように。`minObs` は「今どれだけ強く支持されているか」を表す実効的な値になり、スライダー(1〜8)が意味を持つ。
3. **カービング（Phase 6.2）**: 浮きは消えるが遅すぎた → 6.4 で実効化（実機確認済）。**既知の限界**: 俯瞰プレビューは削除を反映しない(暫定)。2cm ライブ色は最初の色で固定。
4. **超広域の範囲（Phase 6.1 で 200 万まで拡大済み・実機で 966k まで確認）**: さらに広い場が必要なら SoA 化(省メモリ)か走査解像度可変を検討。
5. **キャッシュ対策**: 画面に `build:` 時刻を表示。古い版を見てしまったら `?v=<番号>` を付けて開くと最新が読める（GitHub Pages は index.html を ~10分キャッシュするため）。

## Phase 5 レイアウト実機確認記録（2026-07-23 / `build: 10:24Z`）

- 上下分割 OK: 上=AR カメラ＋その場ボクセル、下=俯瞰プレビューがスキャンで育つのを同時に確認（風鈴のある室内）。原点十字・スケールバー・カメラサムネイルも表示。向きも自然。→ **レイアウトの完了条件は満たす**。

## Phase 6.1 実機確認記録（2026-07-23 / `build: 21:13Z`）

- **範囲拡大 OK**: `ボクセル(2cm) 966,022 セル`（旧 60 万上限を大きく超過）で `FPS 49`・**非クラッシュ**。→ 範囲拡大は成功。
- **色の重み付けは体感で分かりにくい**（2cm ライブは最初の色で固定のため）。→ 本質でないので後回し。
- **本質的な指摘（→ Phase 6.2）**: 何もない空間の**浮きボクセルが近づいても残り、裏の壁/物を隠す**。近づいたら消してほしい。また「マイクラのようにグリッド状の塊」が最終イメージ（内部は元々 2cm グリッド整列。見た目が散らばるのは充填率 0.55 とノイズのため）。

## Phase 6.2 実機確認記録（2026-07-24 / `build: 02:11Z`）

- カービングで浮きは**一応消える**（`一応中に浮いているボクセルは消えてる`）。充填 0.9 で塊感は出た。
- **本質課題の特定**: スキャン精度が低く、別角度に動くと中に浮くボクセルが結構出る。`ボクセル 88〜92 万`・`描画 250,000/250,000`（上限飽和）・`FPS 24〜32`（充填 0.9 のオーバードローで低下）。→ ノイズ低減が必要 → Phase 6.3。

## Phase 6.3 実機確認記録（2026-07-24 / `build: 11:53Z`）

- 「スキャン安定性スライダーって結局どんなパラメータ？変更してもよく分からない」→ **設計不備を特定**。占有値が無制限に増えるため、しきい値もカービングも実質無効化していた（上記「ブロッカー 1」の数値参照）。→ Phase 6.4 で占有上限を導入。

## Phase 6.4 実機確認記録（2026-07-24 / `build: 22:48Z`）

- **スライダーが明確に効くようになった**: `ノイズ除去 1/10` → `描画 153,902`、`8/10` → `描画 12,654`。缶やテーブルの形は残り浮きノイズだけが落ちる。`FPS 32〜37`。セル数も 88〜92 万 → **15 万台**に激減（占有上限＋カービングが効いている）。→ **Phase 6.4 合格**。
- **新たな指摘（→ Phase 6.5）**: 「近くでスキャンして精度が上がっても、遠くから同じ場所が写り込むとまた精度が落ちるのでは？」→ その通りだったので観測品質ロックを導入。

## Phase 6.5 実機確認手順（観測品質ロック — 開発機不要）

1. マージ → Actions 緑 → Pixel で `https://kyoujyu88.github.io/VoxelWorld/?v=16`（`?v=` でキャッシュ回避、番号は任意）
2. `build:` 時刻が **`22:48Z` より新しい**ことを確認
3. **本命の確認**: ある場所（机の上の物など）を **近く（50cm 前後）でしっかりスキャン** → いったん **離れて（2〜3m）同じ場所を長めに写す** → **形・色が崩れないか**（従来は崩れていたはず）
4. 統計に **`低品質を拒否 N 件`** が出るか（＝遠距離観測が実際にブロックされている証拠）
5. 逆方向も確認: 遠くから作った粗いボクセルに**近づくと**、ちゃんと更新・除去されるか（近い観測は許可される）
6. スクショ（近接スキャン後 → 遠方から写した後 の 2 枚）＋「遠くから見ても崩れない？」を返してほしい

> ルール: 各セルは「最も近くから観測した距離」を覚え、その **1.5 倍より遠い観測は無視**（追加も削除もしない）。近い観測は常に許可。→ 品質は上がる一方。**残る限界**: 遠距離観測が**未観測の場所に**新しい誤セルを作ることは防げない（近づけばカービングで消える）。目立つようなら生成距離の上限も検討する。
