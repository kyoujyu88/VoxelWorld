## 現在のブロッカー / 要判断

1. **精度の根本刷新（Phase 7・実機未確認）**: Phase 6.5 まででも「面が厚い殻」「別角度で浮きが増える」が残ったため、先行手法を調査（`docs/RESEARCH.md` の追加調査を参照）。**標準は占有カウントではなく TSDF フュージョン**と判明し、方式ごと刷新した。旧来の場当たり的対策（品質ロック・占有上限・カービング強度）の多くは、TSDF の重み 1/z² と重み飽和で原理的に置き換わる。**要実機確認**: 面が 1 層になるか、浮きが自然に消えるか、FPS（1 点あたり 1 セル → 帯 4〜5 セルに増えたので `STRIDE` を 2→3 に調整済み。デスクトップ実測 ~2.8ms/frame）。
2. ~~**遠距離の観測が近距離スキャンを劣化させる（Phase 6.5）**~~ → TSDF の重み設計に統合（下記は経緯として保存）: ユーザ指摘「近くでスキャンして精度が上がっても、遠くから同じ場所が写り込むとまた精度が落ちるのでは？」→ **その通りだった**。3 経路すべてで劣化していた: (a) 色は 1/d 重みでも遠距離観測が**累積し続ける**ので近距離の色を薄める、(b) 占有は距離無関係に +1 で、遠距離ノイズが**きれいな面の周りに誤セルを作る**、(c) カービングは遠距離の誤差の大きい深度が「面より奥」と読むと**正しい面を削る**。マップ作成用途なのに品質が単調改善しない設計の穴。→ **セルごとに `bestDist`（最も近くから観測した距離）を記憶し、非対称ルール**を導入: **より近い観測は追加・更新・カービングすべて可**、**`qualityRatio`(1.5) 倍より遠い観測はそのセルに一切触れない**。これで一度近くで撮った所は後から遠くに写り込んでも劣化せず、品質は上がる一方になる。残る限界: 遠距離観測が**未観測の場所に新しい誤セルを作る**ことは防げない（ただし近づけばカービングで消える＝自己修復）。
3. **占有値の無制限増加＝カービング/しきい値が無効化していた（Phase 6.4 で修正・実機確認済）**: Phase 6.3 のスライダーが「変えても分からない」と報告され、原因を数値で特定 —
   - 深度は毎フレーム **3,600 点**（160×90 / stride 2）。1 か所を見続けると 1 セルが **毎秒 +30〜60**、数秒で `count` が数百に育つ。**ノイズも同様に育つ**ため、`minObs` 3 でも 14 でも一瞬で超え、**しきい値として機能していなかった**（＝スライダーが効かない）。
   - カービングの減算は「毎フレーム `CARVE_BUDGET` 個ずつ検査」＝ 25 万描画で **1 周 0.5〜1 秒 → 毎秒 −2 程度**。加算 +30〜60/秒 に対して桁違いに弱く、しかも count が数百まで育っているため **消えるのに数分**かかっていた（＝「一応消える」が「また出る」）。
   - → **占有値に上限 `OCC_MAX`(10) を設定**（色の平均は従来どおり無制限に精緻化）。加算は 10 で頭打ち、カービングは `CARVE_MISS`(2)/回、`CARVE_BUDGET` を 16,000 に増やし、**約 1〜2 秒で消える**ように。`minObs` は「今どれだけ強く支持されているか」を表す実効的な値になり、スライダー(1〜8)が意味を持つ。
4. **カービング（Phase 6.2）**: 浮きは消えるが遅すぎた → 6.4 で実効化（実機確認済）。**既知の限界**: 俯瞰プレビューは削除を反映しない(暫定)。2cm ライブ色は最初の色で固定。
5. **超広域の範囲（Phase 6.1 で 200 万まで拡大済み・実機で 966k まで確認）**: さらに広い場が必要なら SoA 化(省メモリ)か走査解像度可変を検討。
6. **キャッシュ対策**: 画面に `build:` 時刻を表示。古い版を見てしまったら `?v=<番号>` を付けて開くと最新が読める（GitHub Pages は index.html を ~10分キャッシュするため）。

## Phase 6.1 実機確認記録（2026-07-23 / `build: 21:13Z`）

- **範囲拡大 OK**: `ボクセル(2cm) 966,022 セル`（旧 60 万上限を大きく超過）で `FPS 49`・**非クラッシュ**。→ 範囲拡大は成功。

## Phase 6.2 実機確認記録（2026-07-24 / `build: 02:11Z`）

- カービングで浮きは**一応消える**（`一応中に浮いているボクセルは消えてる`）。充填 0.9 で塊感は出た。
- **本質課題の特定**: スキャン精度が低く、別角度に動くと中に浮くボクセルが結構出る。`ボクセル 88〜92 万`・`描画 250,000/250,000`（上限飽和）・`FPS 24〜32`（充填 0.9 のオーバードローで低下）。→ ノイズ低減が必要 → Phase 6.3。

## Phase 6.3 実機確認記録（2026-07-24 / `build: 11:53Z`）

## Phase 6.4 実機確認記録（2026-07-24 / `build: 22:48Z`）

- **スライダーが明確に効くようになった**: `ノイズ除去 1/10` → `描画 153,902`、`8/10` → `描画 12,654`。缶やテーブルの形は残り浮きノイズだけが落ちる。`FPS 32〜37`。セル数も 88〜92 万 → **15 万台**に激減（占有上限＋カービングが効いている）。→ **Phase 6.4 合格**。

## Phase 7 実機確認手順（TSDF フュージョン — 開発機不要）

1. マージ → Actions 緑 → Pixel で `https://kyoujyu88.github.io/VoxelWorld/?v=17`（`?v=` でキャッシュ回避、番号は任意）
2. `build:` 時刻が **`23:04Z` より新しい**ことを確認
3. **面の薄さ（本命）**: 机や壁を斜めから見て、面が**1 層のブロック**になっているか（以前は上下にばらけた厚い帯）
4. **浮きの自然消滅**: 空中の浮きボクセルが、その空間を**見るだけで**消えていくか（別処理を待たずに）
5. **FPS**: 1 点あたり 1 セル → 視線方向の帯 4〜5 セルに増えた分、`STRIDE` を 2→3 に下げて相殺済み。実機で `FPS` を確認
6. **`TSDF セル`** は表面だけでなく面の前後の帯も含むので、以前の `ボクセル` 数より多く出る（`描画中` が実際の表面数）
7. **ノイズ除去スライダー**: 意味が「累積重み（0〜20）のしきい値」に変わった。既定 3。上げるほど確立した面だけが残る

> 面が薄くならない／穴が開く場合は `surfaceBand`、消えるのが遅い場合は `TRUNCATION` と `FREE_WEIGHT` を調整する。FPS が落ちる場合は `STRIDE` をさらに上げるか帯を狭める。
